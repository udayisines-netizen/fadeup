# FadeUp Design Review

Read:

- `docs/design/DESIGN_SYSTEM.md`
- `docs/design/REFERENCE_PRODUCTS.md`
- relevant parts of `docs/product/FRONTEND_SPEC.md`
- `docs/product/BOOKING_UX.md` when booking is involved

Evaluate the running interface rather than source code only.

Judge against FadeUp principles:

- premium
- minimal
- mobile-first
- social-first
- booking-first conversion
- consumer-grade refinement
- calm hierarchy
- intentional green accent
- strong visual content
- fast interactions
- distinct FadeUp identity

Reject generic AI-SaaS patterns such as:

- excessive gradients
- excessive glassmorphism
- every section inside cards
- giant dashboard tiles
- decorative charts
- excessive glow
- sparkle-heavy AI clichés
- arbitrary animation
- oversized desktop UI squeezed onto mobile

For customer professional profiles:

Book must dominate.

Follow is secondary.

Messaging is not part of the current product direction.

For booking:

speed beats spectacle.

For motion:

use animation only when it improves:

- comprehension
- continuity
- feedback
- perceived responsiveness

Do not let animation slow repetitive user actions.

References such as:

- Fresha
- Planity
- Booksy
- premium consumer social apps
- modern AI-native products

are principle references only.

Do not clone their exact layouts or brand identity.

Inspect representative mobile and desktop sizes.

Return findings ordered by impact:

1. conversion blockers
2. usability problems
3. hierarchy problems
4. responsiveness
5. visual consistency
6. motion issues
7. polish

For R5R:

do not return final design approval on behalf of the human product owner.

Return whether the implementation is technically/design-system coherent and ready for human review.
